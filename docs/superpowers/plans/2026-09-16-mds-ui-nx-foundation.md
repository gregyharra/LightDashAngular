# MDS UI Nx Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Prerequisite for remotes:** Complete this plan before `docs/superpowers/plans/2026-09-16-mds-ui-nx-module-federation-remotes.md`.

**Goal:** Convert `mds-ui` into an Nx workspace with a shippable `shell` app, enforced module boundaries, Tailwind beside Material, and extracted global `models` / `core` / `shared` libraries — without Module Federation remotes yet.

**Architecture:** Host-first vertical slice. The existing Angular CLI app becomes `apps/shell`. Domain types move to `libs/models`, infrastructure to `libs/core`, reusable UI to `libs/shared`. Feature code stays under `apps/shell/src/app/features` until the remotes plan peels it out. Dependency direction is enforced with `@nx/enforce-module-boundaries`.

**Tech Stack:** Angular 20 standalone, Nx (matching Angular 20 — install current `@nx/angular` / `nx` that supports Angular 20), NgRx 20, Angular Material, Tailwind CSS 3.x, ESLint flat or legacy config as generated by Nx, Karma/Jasmine unit tests, Playwright smoke.

**Spec:** `docs/superpowers/specs/2026-09-16-mds-ui-nx-module-federation-architecture-design.md`

## Global Constraints

- Scope: `mds-ui/` only — do not Nx-ify Python packages.
- Tags: every project gets exactly one of `type:models` | `type:core` | `type:shared` | `type:feature` | `type:app`.
- `depConstraints` must match the company table in the spec (`models` → none; `core` → models; `shared` → models+core; `feature` → models+core+shared; `app` → all four).
- `enforceBuildableLibDependency: true`.
- Never tag feature code as `type:shared`.
- Keep `libs/core` and `libs/shared` small; do not move feature pages into them.
- Routing stays in the shell (`apps/shell`).
- Path aliases: `@mds-ui/models`, `@mds-ui/core`, `@mds-ui/shared` (exact strings — use these everywhere).
- Tailwind beside Material (do not remove Material).
- App must remain shippable after every task: `nx serve shell` (or equivalent) works; existing unit tests for touched areas pass.
- UI: Chromium + Firefox; no horizontal page scroll; reuse shared components.
- Work in an isolated git worktree; frequent commits; no secrets; do not commit `out-tsc/`, `dist/`, or `.tmp/`.
- Commit style: `feat(ui): …` / `refactor(ui): …` / `chore(ui): …` / `test(ui): …`.

- [ ] **Step 1: Write a boundary config assertion test**

Create `mds-ui/tools/module-boundaries.spec.mjs` (Node assert, run with node — or a small Jest/Karma-free script):

```js
import assert from 'node:assert/strict';
import { readFileSync } from 'node:fs';
import { fileURLToPath } from 'node:url';
import { dirname, join } from 'node:path';

const root = join(dirname(fileURLToPath(import.meta.url)), '..');

function loadEslintConfig() {
  // Prefer flat config; fall back to .eslintrc.json
  try {
    return readFileSync(join(root, 'eslint.config.mjs'), 'utf8');
  } catch {
    return readFileSync(join(root, '.eslintrc.json'), 'utf8');
  }
}

const text = loadEslintConfig();
assert.match(text, /@nx\/enforce-module-boundaries/);
assert.match(text, /enforceBuildableLibDependency/);
assert.match(text, /type:models/);
assert.match(text, /type:core/);
assert.match(text, /type:shared/);
assert.match(text, /type:feature/);
assert.match(text, /type:app/);
console.log('module-boundaries config markers OK');
```
